# FinSight v0.15：财报 RAG 与工具 Agent

当前修复版 **v0.15.3**：首次动作登记 `plan(requests=[{metric,year,transform}], narrative=true/false)`。清单只含用户要求的指标，不含计算依赖；程序阻止改查未请求指标、禁止跳过未核查目标，并自动保留成功与缺失结果。`finish`不再要求模型手动汇集result_ids。事实编号和原文片段编号统一注册为已观察证据；纯数值问题不会用原文数字填补缺失值。明确没有该年度报告时，检索会返回覆盖范围，提示换关键词无效。旧评分规则保持不变，真实模型是否正确登记任务仍需评测；`completed`不证明清单已经完整理解原问题。

此前修复版 **v0.15.2**：引用允许纯排版空白差异，但输出始终恢复为来源原文，保留匹配模式和字符范围。模型默认只选 `evidence_ids`，程序填入片段，减少长文本重抄；旧 `quotes` 接口仍核验文字、数字和标点。失败动作也会保留在模型的纠错上下文。已建混合索引可继续复用。

2026-09-28修复版 **v0.15.1**：仅对 `data/verified/facts.json` 和 `data/manifest.json` 兼容物理CRLF/LF换行差异；数值、文字等内容仍须严格一致，代码仍校验原始字节。修复不改写数据文件。已有v0.15用户上传新ZIP和SHA256后执行 `sha256sum -c finsight-agent-v0.15.1.zip.sha256 && unzip -o finsight-agent-v0.15.1.zip && bash agent_v015/run.sh doctor`。ZIP仅包含 `agent_v015/`。

这是新的独立实验入口。旧 LoRA、冻结源码、数据和 v0.13/v0.14 实验不改动。本版使用**基础 Qwen3.5-9B + vLLM/MTP**，不加载旧 LoRA；旧适配器的工具协议与本版不同，待协议稳定后再训练对照。

## 系统怎么工作

```text
已核验来源的 PDF / pages.jsonl
    → 按页分块（512字符，重叠80字符，保留原文）
    → BM25 中文双字词索引 + BGE-M3 dense CLS 向量
    → 公司、报告年度过滤 → 两路排名 RRF 融合

用户问题 → 公司/年度/口径边界检查 → Qwen登记目标清单 → 生成工具动作
    ↔ report_search：检索相关片段
    ↔ read_page：展开检索命中的页
    ↔ financial_metric：指标依赖图 → 已核验事实 → Decimal计算
    → finish：选择已观察原句；程序自动汇集目标清单的已检查结果（含缺失）
    → 程序核验 → 中文内容、页码、原始来源、JSON轨迹、HTML报告
```

模型真正决定下一步用什么工具，并根据工具结果继续行动，最多10步。工具错误会反馈给模型；重复动作被拒绝。生成达到上限或上下文不足会停止并保留记录，不包装成“数据不存在”。

问答采用**原文摘录 + 确定性指标**的第一阶段交付形式。模型不能自行填写最终数字，引用必须是本次观察到的原句；这能核验引用存在，但不能自动证明选句相关、因果解释正确或已完整回答所有要求。`completed` 表示协议执行完成，`completeness_verified=false` 表示问题覆盖仍需评测。自由撰写长篇投资分析、自动补全任意表格字段，尚未实现。

原财报已经完成PDF抽取，本版复用其页文本。建索引时重新检查所选PDF哈希和页元数据，索引绑定页文件、配置、模型和向量文件哈希。原文是未经逐项数值审计的证据；目前已核验事实仍是216条、6种原始字段。不以RAG搜到的某个数字替代缺失事实。

## 上传与执行

只上传 `finsight-agent-v0.15.5.zip` 和同名 `.zip.sha256`，放到：

`/calc/users/geyuboao/workspace/FinSight`

依赖服务器已成功安装的 v0.13 环境、基础模型、BGE-M3、财报和已核验事实。无需管理员权限、联网下载或重传模型。

```bash
cd /calc/users/geyuboao/workspace/FinSight
sha256sum -c finsight-agent-v0.15.5.zip.sha256 &&
unzip -o finsight-agent-v0.15.5.zip &&
bash agent_v015/run.sh doctor
```

默认物理GPU1。可用 `FINSIGHT_GPU=0 bash ...` 指定其他空闲卡。先看 `nvidia-smi`，不要占用其他任务使用的卡。

第一次在基线Python环境中构建混合索引，BGE在GPU运行；进度逐批输出，保存于 `run.log`：

```bash
bash agent_v015/run.sh index --split validation --retrieval hybrid --device cuda:0
```

默认只建美的、中兴6份年度报告的索引。需要训练公司交互查询时，使用 `--split development` 构建30份报告索引，并在后续问答同样指定该参数；比亚迪、迈瑞保留为独立测试公司，不提供本轮开放查询。

检索本身可单独检查，完全不加载9B模型：

```bash
bash agent_v015/run.sh retrieve --question '中兴通讯2024年客户信用风险的管理措施'
```

然后运行一个同时需要检索和计算的问题：

```bash
bash agent_v015/run.sh ask --question '中兴通讯2024年毛利率是多少，并摘录年报关于客户信用风险的管理措施。'
```

交互入口一次加载后复用模型。BGE查询向量在CPU生成，避免与9B模型争用显存；原文向量已持久化，不会每次重算：

```bash
bash agent_v015/run.sh chat
```

默认 `--thinking off`，每步最多1024个生成token。可以显式试验 `--thinking on --max-tokens 8192`；这是可选对照，不自动扩大预算，也不承诺思考开启提高正确率。未启用约束解码，JSON动作由程序严格检查，格式错误允许后续纠正。

每题需要完整公司和年度。目前不继承上一题上下文；输入 `exit` 退出。交互输入期间无后台心跳输出；非交互长任务有日志和30秒进程心跳。心跳只说明进程尚未退出，不表示GPU计算有进展。

## 系统诊断与导出

v0.15.5 推荐用下面的命令，在同一进程复用模型，分别执行原13题和自然问法28题，并自动导出本次结果：

```bash
bash agent_v015/run.sh evaluate --suite all --export-after
```

结果目录中 `diagnostic/` 是原13题（题目和评分没有修改），`natural/` 是新增28题，顶层 `summary.json` 分组列出成绩。新题只使用美的、中兴验证公司：24题需要模型、4题前置检查。包括自然改写、代码输入、多指标/多年份、同比增长率/百分点、部分缺失、母公司口径、比较列不一致、未知指标、模糊同比和伪造数值请求。叙述部分复用4种已审阅主题，不能称为新主题盲测。

`natural_v1.json` 在服务器实跑前冻结目标、数值、单位、来源、缺失状态和叙述锚点。参考值由独立Decimal小公式生成，未调用生产财务引擎；参考不传给模型。评分记录目标清单、结果、来源、错误动作、句子选取数量。题目通过不要求中间零错误；相关性/完整性仍需人工审阅。

仅跑新题：`bash agent_v015/run.sh evaluate --suite natural --export-after`。仅跑原13题仍用下面的旧命令。

```bash
bash agent_v015/run.sh evaluate
```

13题：4题年报原文、4题指标/缺失口径、1题检索计算混合、3题前置边界、1题要求伪造数字的指令干扰。只使用验证公司，不属于独立盲测。前置拒绝单独标明，不能合并宣传为模型正确率。

输出分别记录：预设检索词的目标页命中@6；数值/单位/缺失状态；叙述选句的目标页与关键词代理检查；模型调用次数和耗时；每一步动作、工具反馈和错误。引用逐字检查不等于语义正确率，需要查看HTML/JSON人工复核。检索测试共5项，其中混合题复用了信用风险主题，实际为4种原文主题。

检索对照无需模型：

```bash
bash agent_v015/run.sh index --retrieval bm25
bash agent_v015/run.sh evaluate --retrieval bm25 --retrieval-only
bash agent_v015/run.sh evaluate --retrieval hybrid --retrieval-only
```

这些是检索组件对照，不是直接RAG、Agent、微调Agent的完整公平对比。后者应在新协议和参考答案冻结后实施。

程序打印 `RUN=日期-时间-编号`。把实际值代入：

```bash
bash agent_v015/run.sh export --run '这里替换为实际RUN值'
```

下载打印的 `EXPORT=...zip` 及 `.sha256`。包内包含运行配置、源代码和输入哈希、索引元数据、每题轨迹、HTML及诊断汇总，不含基础模型和原始PDF。`EXIT=0`仅表示命令正常结束；诊断是否通过看 `summary.json`，单题是否完成看题目 `status`。

## 学代码从哪里开始

1. `cli.py`：输入问题，复用模型，输出产物。
2. `agent.py::answer`：模型动作 → 白名单工具 → 观察结果 → 下一轮。
3. `retrieval.py`：原文切块、BGE向量、BM25和RRF排名融合。
4. `finance.py`、`registry.json`：从v0.13原样复制的指标依赖图，保留Decimal、单位、报表口径和跨年比较列检查。
5. `evaluation.py`：诊断题与评分，明确哪些只是代理指标。

可复用的设计方法：**把可验证的约束写进工具接口，把不确定的选择交给模型。** 本项目让模型选择要查什么，但公司范围、单位、数字和页码由程序核验；做基金数据Agent或研究报告Agent时也可沿用。可以先读“混合问题脚本模型测试”，再把其中一个引用改成虚构文字，观察为什么测试会拒绝它。

后续工作顺序：服务器真实模型验收 → 修正失败类别和补充人工标注 → 开放可溯源叙述生成与字段审核流程 → 冻结工具协议 → 新LoRA训练及公平对照 → Web交互和独立测试。当前不重训。

## v0.15.4 选句接口

检索和展开页返回原始 `text`，以及完整落在该片段内的 `sentences` 列表（编号、原文、字符位置）。模型优先调用：

```json
{"tool":"finish","arguments":{"selections":[{"evidence_id":"本题已观察的ID","first_sentence":0,"last_sentence":0}]}}
```

程序复制连续原文，保存相对片段 `source_span` 和整页 `page_span`，不让模型重新抄写或改写引文。未知ID、越界/倒序/非整数编号被拒绝。表格或长句在当前片段内无法完整分句时可以先 `read_page`；旧的 `evidence_ids` 和逐字 `quotes` 接口仍兼容。这里只是标点和章节边界启发式，不是语义解析，不保证跨页句子完整，也不自动判定选句相关。

复用旧索引，不需要重新嵌入；推理模型、LoRA状态、预算、数据和财务公式不变。但提示词及观察内容发生变化，所以必须重新跑服务器模型。本地脚本回放只能证明工具契约和参考值匹配，不是28题模型成绩。

## v0.15.5 协议和规划修复

保留v0.15.4真实成绩：原诊断12/13，自然问法21/28（模型17/24、前置4/4）。全部41题、参考值和两套评分逐字节不变。

- `action_contract.py`把单一已知工具的`{"plan":{...}}`写法规范为`{"tool":"plan","arguments":{...}}`，然后继续按工具参数校验。拒绝多工具、未知工具、重复JSON键；不修改metric、year或transform。轨迹保留原输出和`action_normalization`记录。
- 选句同时附带相同来源的整段ID时，保留选句并移除冗余整段指定；不同来源混用仍拒绝，不静默丢弃引用。编号依然逐项核验。
- 失败动作的重试取决于任务状态。补齐目标结果或观察到新证据后可重试相同finish；无状态进展的重复失败和已成功的重复读取继续拦截。总步数上限仍为10。
- 提示词统一采用完整JSON示例，主推selections接口；目录提供已有指标的公式与别名。说明用户目标与计算依赖、比例与金额、同比增长率与百分点的区别。参考题答案不传给模型。

本版是应用层格式兼容、校验和提示词修复，没有启用token级约束解码或修改vLLM环境。模型仍可能理解错目标；格式修好不代表答案正确。特别是N01的原服务器输出回放现在能第7步结束，但因为多报收入/成本，原评分仍判失败。
