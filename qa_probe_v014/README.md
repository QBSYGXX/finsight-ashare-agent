# FinSight v0.14 多题诊断脚本

这是依附于已发布v0.13推理环境的独立测试包。默认使用vLLM＋MTP、基础模型、原生思考，
每题max_new_tokens8192、上下文16384、seed42。模型只加载一次，依次运行32题。
此包不更改推理引擎、金融工具、训练数据、适配器或旧测试成绩。

## 运行

把 `finsight-qa-v0.14.zip` 和同名 `.zip.sha256` 上传至
`/calc/users/geyuboao/workspace/FinSight`，执行：

```bash
cd /calc/users/geyuboao/workspace/FinSight
sha256sum -c finsight-qa-v0.14.zip.sha256 &&
unzip -n finsight-qa-v0.14.zip &&
bash qa_probe_v014/run.sh --gpu 1 --background
```

若之前的交互问答还在运行，先在其终端输入exit，释放GPU 1；不要直接终止未知进程。
无需重新安装依赖，也不需要再传6GB的环境包。脚本显式设置FINSIGHT_ROOT，解决嵌套metrics目录的根路径问题。

后台启动返回PID、日志路径和tail命令。日志每30秒有心跳，每题有CASE_START/CASE_END。
首次模型加载仍可能需要数分钟；整轮时长取决于每题实际生成长度，约需十几至几十分钟。
每次运行最长2小时，超时停止本任务自己的进程组并保留日志，不影响其他GPU任务。

列出所有题目（不加载模型）：

```bash
bash qa_probe_v014/run.sh --list
```

仅测试部分题目，或使用普通vLLM做同题对照：

```bash
bash qa_probe_v014/run.sh --gpu 1 --ids Q01,Q07,Q16,Q23 --background
bash qa_probe_v014/run.sh --gpu 1 --backend vllm --background
```

同一张GPU上的任务应串行运行。重复运行会创建新的独立产物目录。

只使用中兴通讯和美的集团两家验证公司；清单外代码601398用于预检边界，不检索其财报。
未使用比亚迪、迈瑞医疗等独立测试公司。

## 如何评分

- 数值/缺失数据题：公司、年份、口径、金额单位、指标和变换计划必须完整匹配；
  返回状态、各项数值、单位、事实ID及来源记录哈希必须与固定参考一致。
- 固定参考由人工指定的结构化意图通过原有确定性财务工具生成，不让待测模型生成答案。
  因此主要验证解析、计划和工具流程；参考与执行共用财务引擎，不能声称独立验证全部财务公式。
- 拒答/澄清题：检查预期状态、无数值执行；需要预检解决的题还要求没有模型调用。
  不把invalid_plan、generation_limit等模型失败一律当作安全拒答通过。
- 统计单独列出model_called与preflight_only，另按题型统计。
  当前设计有21道查询/数据边界题、1道需模型处理的未登记指标题、10道预检题。
- 这是已知事实快照上的诊断回归集，非独立盲测。全套通过不代表开放财报问答正确率100%。

模型调用保留完整输入与生成记录；数值答案来源于工具。程序不会从思考中的JSON直接执行。
每题独立，无跨题对话记忆；前题的生成记录会在下一题清空。

## 看结果与导出

每次结果目录：`outputs/qa_probe_v014/<时间戳>/`。

- `summary.json`：选定题数、执行题数、通过、失败、未执行，以及模型/预检分组。
- `report.html`：可在本机浏览器打开的总表。
- `cases.json`：每题状态、耗时、模型调用次数、生成统计与失败检查项。
- `Qxx/trace.json`：完整金融工具结果；`assessment.json`：题目、参考和评分理由。
- `Qxx/model_calls.json`：本题模型调用记录。预检题为空数组。
- `run.log`、`request.json`、`status.json`和文件哈希清单保留运行证据。

正常跑完即使有题目失败，也会`EXIT=0`，表示测试流程执行完成；必须同时查看PASSED/FAILED。
引擎崩溃、环境异常或超时则`EXIT=1`，未执行题保留在统计中。最后自动输出EXPORT ZIP及SHA256，
将这两个文件下载回本机`_release_work`即可核验。

首题耗时可能包含模型加载；比较每题生成速度时使用generation中的秒数与token数，
不要把首题总耗时与后续题直接相比。

## 本地验证与版本边界

构建脚本 `scripts/build_qa_probe.py --check` 在临时目录中装配已发布协议和固定事实，
核验32题意图可执行性、预检预期、根目录初始化和评分器。另用假模型执行完整worker流程，
人为注入一道无效JSON，验证它记录失败并继续，且只加载一次模型。
假模型结果只在临时目录中使用，不进入发布包、不作为模型成绩。

本机没有执行真实GPU上的32题；服务器运行后才能报告实际通过率。
脚本绑定既有v0.13发布清单和冻结事实；若校验不匹配，应排查版本，不要关闭校验。
