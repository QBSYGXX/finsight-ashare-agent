# 新协议LoRA v0.16：训练准备与验证记录

日期：2026-09-28。起点：v0.15.5阶段交付版。用户本轮明确要求新协议LoRA微调，因此新增独立`lora_v016/`实验；不撤销阶段收尾，不覆盖旧LoRA、数据或评测。

## 目标与对照

当前基础模型已能完成财报RAG和工具查询，但有同比规划、目标与依赖混淆、错误后结束困难等行为。实验检验：在工具和提示词固定的前提下，协议对齐的监督微调能否改善这些行为，同时不损害原文引用和缺失处理。

本轮不训练财务数字记忆，不修改已核验事实。采用原生非思考模板，学习每个状态下的下一条JSON工具动作。不能据训练loss降低或脚本教师成功，预告真实Agent提升。

## 数据产物

仅8家训练公司，690条执行过的规则示范轨迹、2,273条动作样本。原始金额/派生指标/多指标/比率意图/同比/缺失/部分缺失/拒绝/用户数字篡改/原文/混合/恢复共16类。其中96条同比轨迹、21条原文、21条混合、8条错误恢复。42条原文相关轨迹包含38个读页动作。

3个公司年度没有找到适合的短句，显式记录并排除其原文与混合任务。语料未读取原13题或自然28题的参考答案，也未使用服务器验证题模型输出作为训练对话；与验证相似的通用行为类别不构成独立盲测。

训练数据使用当前工具返回作为观察，属于协议示范，不是独立的财务真值评测。原文监督目标仅为包含指定业务词的完整原句，不把启发式选择包装成专家分析标注。全文扫描没有验证/独立测试公司名称或代码；事实、页和PDF来源受原清单核验。

## 关键实现

1. `corpus.py`通过真实`agent_v015.answer`执行教师动作，保存模型下一次应看到的完整messages。故意过早finish只保留为错误上下文，不把错误行为当作训练标签。
2. `tokenization.py`使用部署时的原生模板，校验token前缀不变、动作/EOS往返一致，system/user/工具/历史/空think全部为-100。超长中止，不截断和偷删证据。
3. `train.py`固定BF16、rank16/alpha32/dropout0.05、学习率1e-4、2轮、有效batch32，仅语言Linear。尾部损失只生成当前动作所需logits，减少长历史×大词表的显存开销；服务器随机小Qwen先对比完整masked loss及反向传播，再检查手动合并公式与PEFT一致。
4. 20步探针覆盖每类最长样本；单独进程核验已保存适配器的所有张量精确恢复、loss有限、生成非空。探针与正式训练配置/数据/模型/GPU数量绑定；正式训练从基础模型重新开始，不接着探针权重训。
5. `merge.py`直接在原始safetensors分片叠加语言LoRA，保留未训练的视觉与MTP权重。全部输出张量读回比对，不修改原模型；额外空间检查防止合并中途磁盘不足。
6. `evaluate.py`以同一环境、提示词、预算、索引、工具和评分，分别重跑基础模型和合并模型各41题，保留新增通过、退化和共同失败。使用最终轮适配器，不围绕验证分数挑checkpoint，独立测试公司不开放。
7. `launch.py`按阶段运行，后台日志、PID、30秒心跳与无输出提示齐全；失败即停止并导出当前诊断，结束输出真实退出码。仅清理自己启动的进程组，不操作其他GPU任务。

## 已完成本地验证

- 690条教师轨迹真实工具执行通过；2,273条标签全部为规范工具动作，训练公司隔离及8条错误恢复不监督错误动作检查通过。
- 使用本地tokenizers 0.22.1及快照原生Jinja模板，对全部2,273条样本进行前缀、标签、EOS与长度检查；Jinja文件与tokenizer_config内模板逐字一致。最长9,052 token，最大动作90 token。
- 4条样本超过8,192 token，故训练上限设为10,240；仍在当前推理16,384的上下文范围内。保留全部样本，服务器会用真实AutoTokenizer重复检查。
- 既有67项Agent测试＋16项新测试，共83项通过，退出码0。新测试覆盖标签掩码、模板/分词边界拒绝、超长拒绝、纯语言目标、合并键清单、训练隔离、恢复、探针覆盖和对照退化保留。
- Python AST与Git差异检查通过。本机未安装Torch/Transformers训练运行时；没有在本机执行9B反向传播、合并或vLLM推理。

本地分词检查只在忽略目录安装tokenizers，不改系统Python包、不打包这个本地辅助依赖。服务器使用已有离线环境，无新增联网安装。

## 尚需服务器验证

随机小模型的实际API/损失/梯度检查、9B显存与DDP兼容、20步探针、2轮训练、适配器重载、完整权重合并、vLLM/MTP载入新模型、82题对照。以上均为本包待执行步骤，不是本地测试已证明的结果。

完成标准是各阶段真实完成、保存可复核适配器和配对成绩；不要求新LoRA一定优于基础模型。即使退化也保留结果，届时再判断继续采用基础模型还是新LoRA。使用步骤见[新LoRA操作说明](../../lora_v016/README.md)。

可复用经验：训练样本必须匹配部署时的输入格式与目标行为；错误历史可以教恢复，但不该让损失函数奖励错误动作。接口一致、数据隔离和公平对照先成立，才能解释微调收益。
