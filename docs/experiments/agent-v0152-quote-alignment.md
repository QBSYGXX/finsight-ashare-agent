# v0.15.2：引用排版对齐与错误反馈修复

2026-09-28，服务器 `20260928-101603-e074c2cf/question-1.json` 的混合问答达到10步上限。

逐步记录显示，第1步检索、第2步毛利率工具调用成功，第3步开始的finish被字符串严格匹配拦截。将第3步三条引用分别与本地同一快照的 `000063-2024:p45:c864`、`p211:c432`、`p211:c0` 对照：原始字符串均不匹配，忽略空白后均完整匹配。实际原因是模型去掉了PDF排版换行和缩进，不是这三条引用改写了原文实质内容。

另外，原循环仅在成功调用后写入assistant动作，失败时只追加错误提示。下一轮模型看不到自己之前失败的具体动作，纠错反馈不完整。

修复：

1. 优先精确匹配；否则仅对齐空白字符，要求去除空白后完全一致且位置唯一。数字、文字、标点均不模糊匹配。
2. 使用对齐位置从证据切回原文，最终引用保留原始空白，不直接采用模型重写内容；记录 `match_mode` 与 `source_span`。
3. 增加 `finish(evidence_ids=...)`，默认让模型选择已观察片段编号，由程序填入原文。旧quotes接口保留上述核验。整段选取可能含邻近上下文，仍需检查与问题的相关性。
4. 失败assistant动作写入后续纠错上下文；已解析动作保存为干净JSON，移除原生模板结束标记，详细错误指出对应证据编号。

验证：32项回归通过；13条真实财报脚本轨迹通过；服务器第3步原始finish动作三条引用全部通过新核验，程序结果为毛利率37.9127%。这些是程序回归/已观察动作回放，不代表新提示词下真实模型已经运行，也不代表本题或整套模型评测的新准确率。
