# FinSight项目讲解与面试提纲

状态：2026-09-30阶段收尾。基础系统可用，新协议LoRA实验完成；目前不再扩功能或追分。

## 一分钟介绍

这个项目面向年度财报查询。我基于开源模型和FinSight的工具调用思路，构建了检索、读页、财务计算和引用核验流程。
模型负责判断要查什么、下一步用什么工具；财务工具负责公式、单位和口径，引用从实际读到的原文恢复。
我还完成了协议对齐的LoRA实验与推理加速：微调后自然问法开发诊断从24/28提升到27/28，工具错误减少，
但发现原文任务退化，因此同时保留基础模型。另一个固定负载实验中，vLLM＋MTP相对原环境达到约5.07倍生成吞吐。
这些均有配置和轨迹支持；尚未宣称独立测试泛化或完整投资研究能力。

如实说明开源复用和AI辅助开发，个人贡献以自己能解释的数据设计、实验判断、代码理解和验收过程为边界。
不要把未独立实现的上游模型或推理内核说成自己开发。

## 跟着一题理解Agent

以“中兴通讯2024年毛利率和资产负债率”为例：

1. 程序识别公司、年度和报表口径，阻止混用季度与年度数据。
2. 模型输出plan，登记两个用户目标，不把收入/成本等计算依赖当成额外用户需求。
3. 模型调用financial_metric。毛利率由收入、成本计算，负债率由负债、资产计算。
4. 工具返回数值、单位、页码、事实ID或明确失败原因；结果写回上下文。
5. 模型结束任务，程序汇集已检查目标，保留JSON轨迹和HTML结果。

若问信用风险措施，就使用report_search和read_page找到原文，再选择句子。原文检索与结构化数值有不同的证据要求。
Agent的关键是“动作—工具反馈—下一动作”的循环，不是只发一次提示词；目前是单Agent多工具，不是完整多Agent系统。

## RAG与财务工具各解决什么

BM25捕捉术语，BGE-M3提供语义匹配，两者经RRF融合；按公司、年度过滤，片段保留页码和字符位置。
原文适合回答文字证据问题，但检索到一个数字并不自动证明其单位、报告年度、比较列和合并口径。
财务工具使用已核验事实与登记公式，Decimal计算并检查同比可比性；缺净利润不能用归母净利润替代。
引用逐字匹配只证明来源存在，不能证明选句相关或完整，因此仍需要语义评测和失败分析。

## 本轮微调到底教了什么

690条规则教师轨迹通过真实工具执行，拆成2,273个“给定历史，预测下一动作”的样本。
不是教模型背财务数字，也不是人工专家投资分析标注。只有当前JSON动作和EOS参与loss，工具观察与历史标签为-100。
语言层使用BF16 LoRA，rank16/alpha32，2轮、有效batch32；本次实际单卡144步。视觉和MTP冻结。
先检查小模型损失、分词和最长样本，再20步探针、重新加载、正式训练、合并和同轮基础/新模型对照。
动作尾部loss避免为全部长历史生成大词表logits；服务器先与完整masked loss比较，不能只凭“省显存”假定数学等价。

合并时保留原分片所有张量与MTP，不能用一次普通重存就假设MTP仍然存在。原始基础模型没有覆盖。
loss变小只说明示范拟合，不证明自然问答变好；采用同一工具、提示词、索引、评分和推理配置来检验效果。

## 速度如何解释

总等待包含模型加载、输入处理、多轮生成和工具执行。限制思考预算主要减少输出token，之前并未提高token/s。
vLLM/MTP对照使用相同卡、提示词、精度、采样、固定512token及预热，吞吐23.31→82.20→118.17 token/s。
这是整套环境的收益，含prefill、不含启动，且Torch/CUDA版本变化；不能声称全由MTP贡献，或每道问答都快5倍。
新LoRA模型调用179→129次、错误动作26→4次，说明流程更短；这又不同于推理内核每秒吐token的能力。

## 最值得讲的失败

- 旧微调模板验证高分，但去掉股票代码后猜错中兴代码；通过补代码配对实验定位，再加入统一公司解析。
- 直接检索基线没有拿到评分要求的事实ID，比较存在接口不公平；不能宣传原16%到100%的整体提升。
- 毛利率同比可能指相对增长率或百分点，不能让模型暗自选择；最新N26仅拒答，并未真正追问。
- 训练参数随Transformers版本变化，v0.16在加载后报错；v0.16.1将接口门禁前移，并保持训练配方不变。
- 新LoRA的R02把文字任务当成无需检索，直接拒答；N13在错误页上循环，说明协议示范不能保证检索泛化。
- N13两边评分都失败，但基础模型有相关原文、新模型没有答案，说明只看总分会漏掉退化。

所有回答都快5倍、系统会主动理解所有模糊问法、已通过独立测试。
